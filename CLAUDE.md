# Web Terminal — Claude Code Instructions

## Project Overview
Browser-based terminal manager with multi-server cluster support, WebSocket sessions, and PWA. Runs on Node.js + Express + node-pty.

**In use (owner, 2026-10-06; web client deprecated 2026-10-12):** the **companion app** (`ai-terminal/`, Flutter — Windows desktop, Android) against the server, with **Claude Code** as the agent. **Codex is not used and `app.html` is deprecated:** new UI goes to the companion only, but a server change (wire fields, `/api/*`) must never break `app.html`. Their rules are dormant, not dead — see "Dormant code" below.

**This file is the LAW as a digest**, one line per rule. The full text of every rule and its **evidence** live in `docs/findings/` (index at the bottom); rules the code has overtaken are kept in `docs/findings/retired-rules.md`. **Read the covering findings file before changing an area or reopening an issue it names**; new measurements go there, never here. A findings number holds only for the agent version recorded beside it — a claude release can move it unnoticed by any test, so re-probe on the rig.

**The global rules (`~/.claude/CLAUDE.md`) apply and are not restated:** never kill a process by name or command-line substring (never `taskkill /F /IM node.exe` — here it also races the launcher into a dual-monitor crash loop); no secrets or personal info in tracked files; root cause first, with a regression test; push a PR once.

## Pre-Commit Gates (MANDATORY)
1. **Security review** of all changed files — OWASP Top 10: command injection, XSS, auth bypass, path traversal, secret exposure. Auth middleware covers every new route; Bearer endpoints validate tokens; input is sanitised before a shell, HTML or a file path.
2. **`npx playwright test`** — ALL pass before committing; new functionality needs tests (failing first).
3. **`node -c server.js`**
4. **Bump the artifact the change touches** (the PR gate checks per area): outside `ai-terminal/` → `SERVER_VERSION` in `server.js`; under `ai-terminal/` → `version:` in `ai-terminal/pubspec.yaml`; both → both. Patch = fix, minor = feature, major = breaking. Docs/CI-only changes still bump `SERVER_VERSION` (a "neither artifact" path list would rot); **never bump it for a companion-only PR** (a new version with unchanged server bytes). `SERVER_VERSION` sits on one ~400 KB line (literal + changelog comment): never print or diff it whole; **prepend**, keeping the old body as `Prior <ver>: …`; it can never legitimately shrink (`scripts/bump-server-version.js` touches only the literal; the PR gate fails a shrink).
5. **Update `README.md`** for user-facing features (Features, config docs, Architecture table, Cluster and PWA sections).

## Architecture
Walkthrough: `docs/ARCHITECTURE.md`; full module inventory: `docs/findings/operations.md`.
- `monitor.js` — supervisor: mints `WT_IPC_TOKEN`, spawns worker + web, restarts with backoff, rotates logs. Never kill it outside the cold-restart procedure below (its children die with it).
- `pty-worker.js` — owns every PTY, scrollback, persistence, hook state; survives `server.js` restarts. **A change to `pty-worker.js`, `monitor.js`, or anything either requires (`lib/agents.js` fields, `lib/ipc.js`, …) needs a COLD restart**; `server.js`-only changes hot-reload with PTYs intact.
- `server.js` — Express + WebSocket, auth, cluster proxy, REST; stateless about PTYs (IPC via `lib/ipc.js`, `lib/worker-client.js`).
- **Owners — never add a second copy:** `lib/agents.js` (everything agent-specific) · `lib/user-turn.js` (what a `role:user` turn IS — `classifyUserTurn`, `typedTextOf`; `lib/recap.js` only re-exports) · `lib/ansi.js` (escape stripping; a leaf, ECMA-48 `[0-?]`) · `lib/terminal-size.js` · `lib/scrollback-window.js` (served to `app.html`; ported from the companion's canonical `scrollback_window.dart`) · `lib/blocking-prompt.js` (#190) · `lib/menu-state.js` (#316).
- Pure rules: `lib/submit-frames.js`, `lib/submit-confirm.js`, `lib/agent-ready.js`, `lib/usage-limit.js`, `lib/reconnect-buffer.js`, `lib/task-list.js`, `lib/cluster-token.js` (60 s HMAC). `lib/notification-shape.js` is **instrumentation only** — promoting an unknown notification to a permission ask would park a session on a false "waiting" forever.
- Not served: `terminal.html` (`/s/:id` → **302** to `/app/:id`, #218; `tests/legacy-route-redirect.spec.js` asserts it on the source). `lobby.html` is legacy at `/lobby`; `sw.js` is the PWA worker.
- `scripts/rig/` — isolated rig and real-agent probes. The typing probe and WS latency harnesses in `scripts/` belong to the sanitisation workstream — coordinate first. `WT_LATENCY_DEBUG=1` / `?rtt=1` turn on latency instrumentation.

## Rules that bind — by area
Each line has already cost a bug; the bracketed findings file holds its full text.

### Method (applies everywhere)
- **Ground truth is the transcript/rollout and the PTY bytes — the screen lies** (it cannot tell typed from submitted, or highlighted from chosen). Drive the real path (a real `pty-worker.js` on an isolated pipe, as `tests/worker-submit-cr.spec.js` does); instrument rather than reason about internals. A blank terminal beside a healthy chat lens is a widget fault, not a server one (#81).
- **Report, don't predict:** where some process already made a decision, the wire field is that process's report (#179 submit, #227 `autoResumeArmed`). Sharing a module is not sharing an answer.
- **A widget test cannot prove input or selection behaviour** (synthetic events skip the OS path; "plausible" widget tests passed against #55 and #83). Use the real-input rig: `scripts/rig/probe-drive-windows.ps1` + `tool/compose_probe.dart`, `scripts/rig/probe-drive-selection.ps1 -ShotDuring`; mobile needs a real device.
- **A regression test must fail without the fix — mutate one gate at a time** (a faithful negative fixture can pass because a *different* guard fired, #249). State the predicate, not just the count.
- **A probe must ABORT on a setup failure**, never report a negative; a liveness check on a pid you never found PASSES. A probe spawning `claude` from inside Claude Code must scrub `CLAUDE*` from the child env.
- **Refuse and explain; never sanitise or guess** — an unreadable `config.json` (#264), a blocked selector (#190), an over-cap write (#193). Fail toward showing the user, never hiding.
- **Anchor on content, never on an offset or a viewport edge** (#167/#178 scrollback, #210 tail strip, #176 attach).
- **A detector that writes a keystroke must not match our own source** (#138): match structure (`matchUsageLimitPrompt`, `matchBlockingPrompt`), never a phrase quoted in a comment or test. Build every control/non-ASCII char in source with `String.fromCodePoint` (`tests/control-bytes.spec.js` gates C0/DEL literals only — non-ASCII like U+00A0 has no gate beyond the marker's negative test) — and the **negative** test is the load-bearing one.
- **Check an issue's premise against real data** (#73, #206, #218 each had a false one). Claude writes each transcript content block on its own JSONL line — group by `message.id` (#236).
- **Public repo:** never check in captures (they name sessions, projects, users). Keep the numbers, drop the bytes.
- **Isolated rig:** `node scripts/rig/rig.js up` (port 7999, own pipe/data/config) — never cold-restart production to test a hypothesis. `scripts/rig/verify-submit.js` proves a LONG prompt submits.

### Agents & the registry `[agents-codex.md]`
- **No branching on agent.** `if (agent === 'codex')` in `server.js`, `pty-worker.js`, `app.html` or the companion is the wrong file — add a provider field in `lib/agents.js` (`submit`, `interrupt`, `readiness`, `submitConfirm`, `blockingPrompts`, …). `GET /api/agents` serves the catalogue (picker, tint, composer marker); clients hold no agent table.
- `agent` is `'claude'`, `'codex'` or `null`; **`null` is never coerced to `'claude'`**. An explicit agent is authoritative; only an agent-less session falls back to cross-provider discovery.
- **Submit is CR, never LF, for every agent.** A plain shell and unknown agents never read status from PTY output (OSC 9 is something vim can emit).
- A conversation's wire identity is **`agentSessionId`** (`conversationIdFromPath`); **never fold it into `claudeSessionId`** (Fork runs `claude --resume <that>`). "Terminal live, chat old": check the API first.
- **Task list (#73):** `TaskCreate`/`TaskUpdate` deltas (never `TodoWrite`; the id is only in the result prose) folded from the live hook stream in `server.js` beside `pendingQuestion` — derived state, no dot or push (gaining one moves it to the worker). `TaskList` repairs it; prefer `TaskCreate`'s subject; an unseen create still renders as `Task #<id>`.

### Input & submit — law, not guidance (#55) `[input-submit.md]`
**Submit = the agent actually starts a turn**; text in its prompt box is not submit. The compose bar is the app's text box, not the agent's prompt.
- **Keys by PLATFORM, never by lens.** Desktop: Enter submits, Ctrl+Enter newlines. Mobile (soft kbd, `composeUsesSoftKeyboard()`): Enter newlines, **Send** submits — the Android IME commits Enter as `"\n"` text. The bar is multi-line (`minLines:1, maxLines:5`).
- **`buildComposeSubmission`:** strip trailing newlines (`[\r\n]+$`); if a `\n` remains → `ESC[200~`+text+`ESC[201~`+`\r`, else text+`\r`; **ONE** frame (#44). A soft-wrapped line contains no `\n`. A live `/`-line drops newlines (`composeLiveProjection`), since `\r` would submit it.
- **The worker owns submit timing.** Every agent TUI folds a read into a paste and swallows a trailing CR (Claude from ~80 chars). Text ending in `\r` → text now, lone `\r` after `submit.gapMs`; input in the gap queues behind. A bare `\r` on a cold PTY is never split; one within `gapMs` of a **bracketed-paste close** is withheld (#87) — keep that narrow. **Only a real time gap rescues the CR; never change its bytes.**
- **#213:** a dictated prompt has no newline, so Claude cut its first 1024 bytes. The worker brackets bodies over `submit.bracketAbove` (Claude **512 BYTES**; undeclared means never). A body containing ESC, CR or LF is **never bracketed and never sanitised** — written exactly as is (it may be a paste, an arrow, a live `/`-line). This changes the BODY, not the CR.
- **Esc:** a **lone `0x1b`** (`isEscapeKey`) to a **`working`** session flips it idle at once (Claude fires no hook on interrupt); never from `waiting` (Esc there rejects the tool); no push; a plain shell declares `onEscape: false`.
- **The wire cap and the offline-buffer ceiling are ONE number:** `WS_INPUT_MAX` == the companion's `_inputBufferHardCap` == 256 KB UTF-16 units, compared with `>` both sides; gated by `scripts/check-shared-constants.js`. `WS_MAX_PAYLOAD` (4 MiB) bounds memory and stays far above it, because `ws` refuses by **closing the socket**.
- **Every refusal SAYS SO (#193, `inputDropped`):** the companion refuses at the app cap in `sendInput`, before the live/buffered branch. The cluster proxy reports once per outage, the rule living with its latch in `lib/reconnect-buffer.js` — `buffer-full` or `peer-unreachable` (#209); `giveUp` tallies what was **lost**, latches unconditionally, clears the buffer **before** the close.

### Readiness, blocking screens & submit verification `[input-submit.md]`
- **A spawned agent is NOT ready when its session is (#147)** — a marker, not a timer: `readiness.composer`, `lib/agent-ready.js`, applied in the worker. **Nor is it ready at its composer (#404):** Claude draws it before startup ends, and a CR before its next query (`readiness.settled`, `ESC[>0q`, counted only AFTER the composer) is lost while the words stay; the settle wait has its own 10 s ceiling (`WT_READY_SETTLE_MS`), and the composer alone clears a #190 report. Scan only **after the launch command is written** (shell prompts draw `❯` too). No `autoCommand` → never gated; undeclared agents are ready from birth; any hook forces ready; the 45 s `WT_READY_FALLBACK_MS` is a ceiling, not a detector (withheld while a selector is reported, below, and once the composer is drawn - the settle ceiling owns that wait); a **missing** field reads as ready. **A restored session is never seeded from scrollback.** The live `/`-line is gated too. Clients gate **submit only** and **never auto-send on ready**. Known gap: the latch does not reset when the agent exits to its shell — that fix belongs in the worker.
- **The marker is `❯` + U+00A0 (#190)** — the bare caret is also a selector's cursor. Write it as escapes; keep source ASCII-only; `tests/composer-marker.spec.js`'s negative (`❯` + U+0020) carries the weight.
- **Any write the worker makes itself** (auto-resume `continue`, recovery) checks `session._ready` and **defers, never skips** — before its one-shot is consumed, retrying on `session._autoResumeTimer` so a dead PTY or a returning user cancels it.
- **Claude's startup selector family (#190, `lib/blocking-prompt.js`):** folder trust and "external CLAUDE.md imports" are unnumbered, CHA-positioned (no spaces — render columns first) lists whose **default row is destructive** (`No, exit`): a prompt's trailing CR there kills the agent. Matched by **shape** only until the composer is drawn (#404 — not until ready); **reported unconditionally** (`blockedPrompt`; the submit is refused and explained). While it is reported the #147 fallback is **withheld** — only the composer marker (which clears the report and starts the #404 settle wait) or a hook releases it. Typing an answer is **opt-in** — `autoAnswerBlockingPrompt` / env `WT_AUTO_ANSWER_BLOCKING_PROMPT`, **default OFF** (trusting a folder is the owner's call), only for a declared member, rows counted off the render. Trust is inherited, so no scratch dir reproduces it.
- **A submit is VERIFIED, never predicted (#179).** The worker arms `submitConfirm.timeoutMs` **when the CR goes out**, stops on **any** hook, else publishes `submitUnconfirmed` (pushed, never persisted). **Every gate fails CLOSED** — not armed when the provider declares nothing, no hook ever arrived, the worker wrote it, the session is `working` or compacting, Esc arrives, or the line (accumulated from bytes written, HEAD kept, paste bodies dropped) starts with `/`. Clients restore the words only into an **empty** bar, for a report at/after their own last submit, inside a grace window.
- **Alt-screen marks no blocked state (measured).** A panel over the composer (`/status`, `/usage`, `/model`, Agent View — whose next prompt starts a **different** session) is detected by `lib/menu-state.js` (#316) by **order**: a `readiness.panelFooter` phrase written after the last composer marker. It never causes a write; its one write-side use is a **gate**: the #359 restart hold will not type its wrap-up prompt into an `inMenu` session (`lib/maintenance.js` `canPrompt`), so a false positive skips a prompt.
- **PTY size: the smallest ACTIVE viewer wins** (`lib/terminal-size.js`, in `server.js`); a background socket has no vote. Cache a size only **after the worker accepts it**; nudge (`rows-1`, `rows`) a viewer that changes nothing.

### Transcript & chat lens `[chat-lens.md]`
- **"My last prompt" is NOT `role === 'user'`:** slash-command echoes, task notifications, hook feedback, teammate messages and compaction summaries are `role:user` too, and real prompts carry `<system-reminder>` wrappers. The server classifies (`lib/user-turn.js`) and publishes `userKind`; the companion's Dart `classifyUserTurn` is only a fallback for older servers.
- **Recap** (`GET /api/sessions/:id/recap`): on demand, never on the poll; prefers the author's `## TL;DR` (`lib/speech.js` `extractSummary`); degrades, never 404s.
- **A prompt sent mid-turn is a `queued_command` attachment, not a user turn (#249):** one branch in `lib/transcript.js`, emitted at the attachment's byte position, gated on `commandMode === 'prompt'`; who sent it is the classifier's call (#250 — never re-derive it from `origin`). Build it from `attachment.prompt`, **never `rendered`**; drop image base64. Only the companion has a chat lens.
- **Tail strip (#194/#210):** recognise only the composer marker (from `GET /api/agents`, never retyped in Dart) within `kComposerScanRows = 7` (bounds [5, 8]) of the last row with content — in order to **stay quiet**. The approval/question selector was never measured: say "a screen without the marker", not "every dialog". Never reuse `readiness.composer` as a Codex screen marker (it gates submits).
- **Chat links are TextSpans (#83)** — never a widget in the text flow (a `MarkdownElementBuilder` shatters the paragraph and `SelectionArea` cannot drag). Per-link affordances come from a `TextSpan` recognizer or the selection menu; test the RichText **count** per sentence.

### Scrollback & xterm `[chat-lens.md]`
- **A scrollback byte offset is not a position** (the HEAD is trimmed at 2 MB while `total` stays pinned). Over-fetch, cut where the anchor reappears, **stop rather than guess**: less history, never repeated history or a silent hole.
- The WS attach replay (truncate → sanitise) and `/scrollback` (sanitise → slice) agree over the **tail**, diverge near the **head** (`sanitizeReplay` is stateful): anchor on the end of what is on screen (#176). `tests/attach-replay-overlap.spec.js` pins it server-side — reordering either pass is a server change. A leading `ESC[?2004h` is state, not content: preserve it.
- **The companion vendors patched xterm 4.0.0** (`ai-terminal/third_party/xterm`, #81). **Grep `WEB-TERMINAL PATCH (#81)` before re-vendoring or upgrading** — a plain re-vendor restores the bug. Verify with upstream's suite on both copies (`README-PATCH.md`).

### AskUserQuestion `[questions.md]`
- **The layout decides what keys mean, per QUESTION:** any option with a `preview` → side-by-side, else compact. `hasPreview` travels on the wire, derived from the **RAW** option list (the shaped one can lose a preview three ways); `buildAnswerFrames` alone turns it into keys:
  - compact single, one question: digit submits · compact single, multi-question: digit selects **and advances** (no Enter — it would commit the next tab's default) · side-by-side: digit moves, **Enter commits and advances** · multi-select: digits toggle, **Right-arrow** advances.
- **Notes (`n`) exist only side-by-side** (`↓…, n, <note>, ESC, CR` — that Esc closes the editor; a `waiting` session takes no interrupt). **`Other` exists only compact**; side-by-side's trailing CR would submit an unpicked option. Never both. Multi-select's last row is a checkbox: it alone returns "The user did not answer".
- **Preview body (#145):** own cap `PQ_PREVIEW_CAP = 2000`; monospace and **unparsed** on the selected row only, scrolled into view, with a `fontFamilyFallback`.
- **Only the MAIN agent's next tool resolves a pending question** (`!agentId` on the **event**, #236); `UserPromptSubmit`, `Stop` and the question's own `PostToolUse` stay ungated. **`armIdle` refuses to idle a session owing an answer** (#239) — at arm time, not in `applyIdle` (#129's compact replay). A `waiting` session is never timed out (#230).
- Verify with `scripts/rig/probe-askq-layout.js` — read **which option came back** in `tool_result`; a pending question is not in the transcript at all.

### Auto-resume and kill `[agents-codex.md]`
- **"The user is back" is not "the block is over" (#227):** while cap-blocked a `UserPromptSubmit` **re-arms** (after `clearObservedCapBlock`, on `session.capBlocked` alone). Esc says STOP, a tool event says work runs, only a prompt says GO. Clients render the worker's `autoResumeArmed`, **ABSENT kept apart from FALSE**. Never "fix" the spec by flipping its `capBlocked = true` default (it passes vacuously). `clampPct` rounds 99.5 → 100, so `status === 'working'` at fire time is the **only remaining guard** — never remove it.
- **A ConPTY `term.kill()` is already graceful for the agent (#191):** it terminates the shell; the orphaned agent runs its own shutdown. `/exit` buys nothing, so **Kill stays instant**. Before reopening, read limit 4 (MCP servers; mid-turn and Codex unmeasured).

### Dormant code — read the findings before touching it
- **Codex** `[agents-codex.md]` (unused; its laws bind when you touch it). **NEVER copy `~/.codex/auth.json` into a second `CODEX_HOME`** (the refresh token rotates; reuse-detection can revoke the family). An untrusted `hooks.json` **blocks every new Codex session** — delete it the moment a probe ends and strip `[hooks.state]`. OSC 9 enters `handleHook` with **`hookDriven: false`**, or the API-error sniff types Claude's `continue`/`/compact` into Codex. A rollout path is discovered, never cached forever. Never declare an unmeasured marker or `bracketAbove` (#143).
- **`app.html`** `[input-submit.md]` (deprecated; keep server changes from breaking it). **ONE classic script:** `window.f = () => f()` recurses forever and kills the page — write `window.f = f;`, then load the page and read `pageerror` (a green suite once hid it). Bar visibility (`isMobile`, `innerWidth < 600`) is not platform. Every input write goes through `sendPtyInput` (`tests/app-input-path.spec.js`), which re-coalesces nobody. #263 readiness: the refused submit re-reads the sidebar, and **Send is never disabled**.

## Auth & Security
- Cookie session auth (browsers); Bearer tokens (cluster). `api-tokens.json` and `cluster-tokens.json` are gitignored; each server has its own credentials.
- Mask passwords as `***`; API tokens expire in 90 days; rate-limit logins. **Every new API route sits behind auth middleware**; WS auth takes cookie or query token. The cluster proxy validates a stored token exists before forwarding. Never pass unsanitised input to `term.write()`, `execFile()` or HTML.
- **A route that WRITES config must first prove it could READ it** (#257/#264): `readConfigResult()` separates ABSENT (write) from UNREADABLE (refuse, file untouched, response names no path). A corrupt `config.json` otherwise leaves `PASS`/`_USER` on `'admin'`, opening `/api/setup`, and read-mutate-write over `{}` replaces the file. `tests/issue264-config-write-paths.spec.js` fails on any unguarded route `writeConfig()`. **Still open:** a corrupt config still drops the password to the default at the next start.

## Tests
- Port 17681, `testuser` / `testpass:colon`; `playwright.config.js`. Under `WT_TEST` the processes use `config.test.json`, never the production `config.json`.
- **Redirect, don't back up:** `WT_CONFIG_FILE` (all three processes), `WT_API_TOKENS_FILE` (#272 — keeps the suite out of the production token store), `WT_CLUSTER_TOKENS_FILE`, `WT_CLAUDE_METRICS_FILE`. The per-run reset of those test files (#240) is `scripts/reset-test-run-files.js`, the first half of the `webServer` command — **never at `playwright.config.js` module scope** (every worker and listing re-requires it: it revoked a live run's tokens) and never in `global-setup.js` (runs after `webServer` has read them).
- Serial (`workers: 1`; 10-session limit). `diagnostic`/`mobile-debug`/`paste-diag` specs are `testIgnore`d; `diagnostic.spec.js` hits the LIVE server with `DIAG_PASS` (the `playwright.diag.config.js` its header names is not in the repo).
- **The suite is NOT flaky** — everything addresses `127.0.0.1` (`localhost` resolves to `::1`). A lone failure from a subset run may be a `webServer` race: re-run that spec alone. The full suite (12–15 min) exceeds the Bash 10-minute cap — run it in the background. `AttachConsole failed` is a harmless node-pty warning.

## Deployment & Operations
- Autostart: scheduled task / Startup → `wscript.exe start-server.vbs`. **Never run `node server.js` / `node monitor.js` directly** (console flashing). Port 7681; `config.json` gitignored. **Never stop or restart production without explicit permission.**
- **`scripts/cold-restart.ps1` loads the deps (`scripts/check-deps.js`) before the first kill** — a running process serves deleted modules from memory, so a broken `node_modules` turns a restart into an outage. A wedged worker still owns live PTYs; a monitor that gave up owns nothing. `-CheckOnly` audits a peer.
- **The restart hold (#359) ASKS, never orders (#407):** a cold restart is OK only when every session agrees, and "no"/"later" are accepted. The answer is STATE (`wt-maintenance.js answer` -> `POST /api/maintenance/answer`, behind auth), never parsed from prose; `ready` needs `yes` + turn end + nothing running, `no` is `declined` until the hold is cancelled, `later` is `deferred` then re-asked (max `MAX_ASKS`), silence stays `answering`. Cancel types "called off" to every session it had asked (pending list in `_maint.off`). A different worker (`ping` pid + `startedAt`, #406) counts as restarted; a hot reload keeps the worker. Rules: `lib/maintenance.js`.
- **Never junction or symlink `node_modules` into a worktree** — `rmdir /s` / `git worktree remove --force` follow it into the target (gutted production 2026-07-30). Remove a junction with bare `cmd /c rmdir <link>`.
- **Wedged worker:** `/login` 200 while stateful calls time out, `RPC listSessions timed out` after a first `Failed to create session`, `worker.log` stopped, worker at 0% CPU with an `OpenConsole.exe` but no `bash.exe`. Stop the worker (releases the lock), `npm install`, relaunch — killing that `OpenConsole.exe` does not help.
- **Cold-restart a cluster server from a DIFFERENT server** via its `/api/exec`: (1) `git fetch --all && git pull --ff-only`, verify `SERVER_VERSION` on disk; (2) a detached PowerShell script (temp file, `start /b powershell -WindowStyle Hidden -File …` — the request dies with the server) that kills monitor + worker + server by PID and relaunches `start-server.vbs`. Git Bash spells a PID kill `taskkill //F //PID <pid>`. Match `server.js`/`pty-worker.js` by **full path with `-like`** (`-match` breaks on `\p`); find `monitor.js` by their parent PID.
- Session 0 (S4U task) can have a stale PATH — relaunch from a user session. **No console flashing:** the VBS launcher, `useConptyDll: true` in `pty.spawn`, `windowsHide: true` on every `execFile`/`execSync`.

## Cluster & Workflow
- `config.json`: a `cluster` array of `{name, url}` plus `publicUrl`; `/api/cluster/sessions` skips the server matching `publicUrl` (else duplicates); the companion merges client-side. `passAllEnv` (default false) controls the spawned shell's environment.
- Issues (`Adiel-Sharabi/web-terminal`): check open issues and PRs → assess clarity → **reproduce before fixing** → tests first → full suite → subagents for individual fixes.
